帮 jeff 更新复健错题本 `错题本.md`(仓库根目录)。

## 输入
`$ARGUMENTS` = 用户对这条错题的描述。若为空,就用**本次对话里刚讨论的那道题/那个错**。

## 你要做的

1. 读 `错题本.md`,看清两个域的表格格式和各自最后一个编号。
2. **先判域**:这条属于 **算法(A)**(解题时"需求→数据结构/套路"没连上)还是 **工具/工作流(T)**(git / 构建 / 配置 / 编辑器等工程反射断点)。拿不准就问 jeff。
3. 把这条错题**提炼成一行**,核心是抓「**反射断点**」——不是"代码写错了",而是"**需求 X 应该反射到工具/套路 Y,但没连上**"。填这四列:
   - **题/场景**:题名(算法)或场景(工具,如 `git commit type`)。
   - **反射断点(need → 漏了什么)**:真实需求是什么,结果漏想了哪个标准工具/套路而绕了远路。
   - **教训一句**:压缩成一条可复用的 `need → tool` 反射,越短越好。
   - **日期**:今天(先确认真实日期,别凭对话惯性)。
4. 编号 = 域前缀 + 该域上一条 +1(算法 `A1/A2…`,工具 `T1/T2…`)。追加到**对应域**那张表的末尾,保持对齐。**别跨域混编号。**
5. **只加一行,不写代码,不长篇**。这本的纪律就是"一行说清"。
6. 追加后,把新增的这行原样回显给 jeff 确认;他觉得没提炼到位就改。

## 原则
- 错题本囤的是**教训模式**,不是解法。别把烂代码贴进来。
- 如果这条错因和**同域内**已有某行是**同一类断点**,提醒 jeff:"这是该域第 N 次同类断点了"——反复出现的才是复健重点。
