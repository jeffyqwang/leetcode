## 主解法的关键点

- 本质是「**若干组格子,每组内不许重复**」:9 行 + 9 列 + 9 宫 = 27 组,等于做 27 次 217。考的是二维数组 + 哈希判重,**不是图**(格子之间没有「走到相邻格」的关系)。
- 宫编号:`Math.floor(r / 3) * 3 + Math.floor(c / 3)` —— 先算宫在第几行/第几列,再用「行 × 每行宽度 + 列」压成一维(和 canvas 像素坐标转 `ImageData` 下标同一招)。
- 宫集合必须建在最外层、9 份各自保留到结束;按行遍历时同一个宫的格子不连续,「每 3 格刷新」会清掉前一行的记录。

## 常数优化:实测(合法棋盘,中位数)

| 写法 | 每次 |
| --- | --- |
| 数组 + `includes`(主解法) | 1.57 µs |
| `Set` + `has` | 1.61 µs |
| **位掩码** | **0.22 µs**(约 7×) |

- 复杂度没有优化空间:棋盘固定 81 格,都是 O(1),差别全在常数。
- 数组和 Set 打平:每组最多 9 个元素,`includes` 扫 9 下,哈希没有优势(又一次「只看大 O 会判错」,错题本 A9)。
- 位掩码:每行/列/宫一个整数,第 k 位 = 数字 k+1 出现过。`1 << k` 造掩码,`&` 查,`|=` 记;`'5'.charCodeAt(0) - 49` → 4。

## 真实的数独游戏怎么判

- **增量检查**:玩家每次只填一格 → 只查这格所在的行、列、宫(20 个相关格),不全盘扫。很多 App 手里还有标准答案,直接比对。
- **变体**(对角线、锯齿、杀手、温度计、箭头…)框架不变:
  - 只换分组的(对角线多 2 组;锯齿宫用查表 `regionOf[r][c]` 代替公式)
  - 加关系的(杀手:和等于给定值;温度计:严格递增;箭头:圆圈 = 箭头上数字之和)→ 每条规则一个检查函数
  - 工程上:规则列表 `constraints[]` + 反向索引「格子 → 相关规则」,填一格只跑相关规则
- 真正难的是**出题**:保证唯一解需要求解器(回溯 + 约束传播)。
